# Dirflux 0.1.0-beta.2

First public beta: a self-hosted browser file manager with dual panes, folder uploads, previews, text editing, share links, accounts and recoverable trash.

## Install

- Docker: `ghcr.io/marcvandecoevering/dirflux:0.1.0-beta.2` (Linux AMD64 and ARM64).
- Native: extract `dirflux-0.1.0-beta.2.tgz`, run `npm ci --omit=dev` inside `package`, then `npm start` with Node.js 24.22.1 or newer.
- Unraid: follow the [installation guide](https://github.com/marcvandecoevering/Dirflux/blob/main/docs/UNRAID.md). Apps listing approval is separate from this release.

Preserve `/files` and `/config` separately. The first administrator uses the code in `/config/setup-token` (native default: `data/config/setup-token`).

## Dependencies and boundaries

JavaScript / Node.js 24, Express 5, SQLite, CodeMirror 6 and PDF.js. HTTP/HTTPS, JSON API, SSE and HTTP range requests. Assets are served locally, without telemetry or a CDN. There is no built-in SMB/FTP/WebDAV server or media transcoding.

This is beta software. All accounts share one file tree; public links grant unauthenticated access. Back up both storage directories before updates. Browser codecs determine media compatibility. Mobile workflows, cross-version upgrades and hostile external writers to the storage are not covered by a stable-support promise. See [Security](https://github.com/marcvandecoevering/Dirflux/blob/main/SECURITY.md) and [Parity](https://github.com/marcvandecoevering/Dirflux/blob/main/docs/PARITY.md) for limitations and revision-specific evidence.

Native archive checksums and source/run metadata accompany this release. Container images are loaded from the exact tested CI artifacts and checked after registry publication; they are not rebuilt during promotion. Container vulnerability reports cover known OS/package advisories at scan time, not every possible application vulnerability.
