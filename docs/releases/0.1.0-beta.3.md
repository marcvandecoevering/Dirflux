# Dirflux 0.1.0-beta.3

Simpler Unraid installation: choose your storage folders and initial administrator password in the container form, start Dirflux, and sign in as `admin`.

- Empty `/files` and `/config` mount roots are prepared automatically for `PUID=99` / `PGID=100`. Existing files are never recursively chowned or overwritten.
- The initializer briefly starts as root, then permanently drops groups and user privileges before starting the application. The application has no effective Linux capabilities.
- `INITIAL_ADMIN_PASSWORD` creates an administrator only when no account exists. Existing accounts and passwords are never reset on restart or upgrade. Optional `INITIAL_ADMIN_NAME` defaults to `admin`.
- The `beta` image channel allows ordinary Unraid image updates. Versioned images remain available for controlled deployments and rollback with matching backups.

Existing beta.2 installations: back up both folders, change Repository to `ghcr.io/marcvandecoevering/dirflux:beta`, then apply. Your existing account remains valid. Existing `--user=99:100` configurations remain supported; automatic empty-folder preparation requires the new template's initializer settings.

The initial password is a Docker environment setting visible to server administrators; it is never logged by Dirflux. It can be removed after account creation. Without initial credentials, protected setup using `/config/setup-token` remains available for native or advanced installations.

Use the [Unraid guide](https://github.com/marcvandecoevering/Dirflux/blob/main/docs/UNRAID.md). This remains a beta; full functional parity and all deployment scenarios are not claimed.
